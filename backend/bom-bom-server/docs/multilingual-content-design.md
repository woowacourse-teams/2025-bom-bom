# 다국어 콘텐츠 설계

## 목적과 범위

이 문서는 뉴스레터와 공지의 다국어 데이터 저장, 조회, 어드민 입력 흐름을 정리한다. 한국어는 기존 원본 테이블에서 관리하고, 번역 테이블에는 한국어 행을 만들지 않는다. 현재 지원 언어는 한국어(`ko`)와 영어(`en`)이며, 번역 행은 영어에만 사용한다.

## 뉴스레터 데이터

뉴스레터와 상세 정보를 나누는 번역 테이블을 각각 만들지 않고 `newsletter_translation` 하나를 사용한다. 번역 행은 `newsletter_id`로 원본 `newsletter`에 연결한다. 원본 뉴스레터와 `newsletter_detail`의 기본 키 관계를 이용해 상세 번역 대상도 같은 뉴스레터 번역 행에 저장한다.

| 구분 | 필드 |
| --- | --- |
| 번역 대상 | 이름, 설명, 이미지 URL, 이메일, 메인 페이지 URL, 구독 URL, 발행 주기, 발신자, 지난 뉴스레터 URL, 구독 방법 |
| 원본에서 공통 관리 | ID, 카테고리 ID, 발행 상태, source, 구독자 수, 지난 뉴스레터 조회 허용 여부, 생성·수정 시각 |

한국어 값은 기존 `newsletter`, `newsletter_detail` 컬럼에서 읽고 수정한다. 영어 값은 `newsletter_translation`의 `en` 행에서 읽으며, 행 또는 필드 값이 없으면 해당 원본 컬럼의 한국어 값으로 대체한다. 이미지 URL도 언어별 자산이 제공될 수 있으므로 번역 대상에 포함한다. 모든 언어에서 같은 이미지를 쓰는 경우 영어 행에서 비워 두어 원본 URL을 사용한다.

번역 테이블은 `(newsletter_id, language)` 유일성 제약과 원본 뉴스레터 외래 키를 가진다. 원본 삭제 시 번역 행은 cascade로 삭제한다. 현재 언어 코드는 ISO 639-1 두 글자를 사용하며 컬럼은 `VARCHAR(2)`로 둔다. 한국어를 원본으로 취급하고 번역 언어는 `en`만 저장한다.

## 공지 데이터

`notice`는 한국어 원본을 유지하고 `notice_translation`에 번역을 저장한다. 번역 행은 `notice_id`로 공지 원본과 연결하며, `(notice_id, language)`는 유일해야 한다. 공지 삭제 시 번역 행도 cascade로 삭제한다.

번역 필드는 제목(`title`)과 내용(`content`)이다. 영어 번역이 없거나 필드 값이 비어 있으면 기존 공지의 한국어 값을 반환한다. 대표 공지와 공지 목록 API는 선택적 `language` 쿼리 파라미터를 받고, 생략하면 `ko`를 사용한다. 기존 응답 필드와 대표 공지가 없을 때의 `204` 응답은 유지한다.

## 언어 입력과 검증

API 입력은 문자열로 받고 컨트롤러에서 언어 enum으로 변환한다. `ko`는 원본 조회를 뜻하고, `en`은 영어 번역 조회를 뜻한다. 그 외 값은 공통 요청 파라미터 오류로 거부한다. DB에는 enum 이름이 아니라 소문자 ISO 코드(`en`)를 저장한다.

## 어드민 생성·수정 흐름

어드민은 한국어 원본 필드와 영어 번역 필드를 구분해 전달한다. 원본 값은 기존 원본 테이블에 저장하고, 영어 값은 해당 번역 테이블에 저장한다. 원본과 번역을 함께 수정하는 작업은 한 트랜잭션에서 처리해 부분 저장을 방지한다.

권장 입력 구조는 원본 필드와 언어별 번역 묶음을 분리하는 것이다. 구체적인 어드민 요청 DTO와 엔드포인트는 어드민 저장소의 기존 생성·수정 API를 확인한 뒤 그 규칙에 맞춰 확정한다.

PATCH 의미는 다음과 같이 적용한다.

| 입력 | 의미 |
| --- | --- |
| 필드 생략 | 기존 값을 유지 |
| 명시적 `null` | 기존 어드민 PATCH 동작과 같이 기존 값을 유지 |
| 빈 문자열 | 어드민 요청 검증에서 거부 |

번역 행이 없으면 첫 영어 입력에서 생성한다. 현재 PATCH 계약으로는 영어 번역 필드를 명시적으로 지우는 기능을 제공하지 않는다. 번역 삭제가 필요하면 별도 삭제 계약을 정해야 한다. 공개 공지는 한국어 원본 제목과 내용이 필수다. 영어 번역은 선택 입력이며, 제목과 내용은 부분적으로 저장할 수 있다. 초안 공지의 필수값과 부분 번역 허용 여부는 어드민의 초안·발행 전환 규칙에 맞춰 확정한다.

## 적용 상태와 후속 확인

현재 서버 구현은 뉴스레터 번역의 `name`, `description` 조회와 공지의 `title`, `content` 조회를 우선 반영하고 있다. 위 표에 적은 나머지 뉴스레터 필드는 모두 구현된 상태가 아니며, 어드민 저장 경로도 별도 확인이 필요하다.

다음 사항을 어드민 저장소와 함께 확인한다.

1. 뉴스레터와 공지의 생성·수정 API 및 호출 경로
2. 어드민 화면에서 원본과 영어 번역을 함께 저장하는 방식
3. PATCH의 생략, `null`, 빈 문자열 의미
4. 초안 공지의 제목·내용과 부분 번역 허용 규칙
5. 번역의 모든 값이 제거될 때 번역 행을 삭제할지 유지할지
